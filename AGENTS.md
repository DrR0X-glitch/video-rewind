# Project documentation

> All planning and information material is in `docs/`

# Task tracking

Keep the live task register in `docs/IN_PROGRESS.md`; it contains only current in-progress work and backlog items, not completed-task history. Before creating a commit, update it to reflect the work included in that commit, remove tasks completed by the commit, and add any remaining testing or follow-up as separate current tasks. Bug fixes discovered afterward should be added as separate bug tasks rather than reopening a completed task.

# Git workflow

Before making Git changes in a session, read `docs/GIT_WORKFLOW.md` once for branch naming, local verification, and merge rules. There is no need to reread it before every change in the same session.

# Styling Reference

Read `docs/STYLING_REFERENCE.md` each session if UI edits will be made.
